# 页面精简规范

## 1. 目标与边界

减少用户需要阅读、辨认和操作的负担，让核心内容与下一步行动更清楚，同时保留页面的个性、氛围和设计巧思。留白可以保留，不用文字或装饰填满。

适用于已有页面的审查和精简，也适用于用户明确要求遵循本规范的新界面。可以删减或合并冗余模块，调整层级、布局和交互；保留用户指定内容、业务功能与视觉身份。不自动扩展为品牌重塑、全站重建或业务流程改造，不判断页面由哪个模型生成。

“必须／不得”是约束；“建议”可按场景调整。用户要求和项目规范优先。

## 2. 判断依据

对文字、模块、装饰与操作步骤，检查它在当前位置承担的具体职责：

| 职责 | 有效作用 |
|---|---|
| 识别 | 说明页面、内容、分类或对象是什么 |
| 行动 | 提供可执行入口，说明必要后果 |
| 状态 | 显示真实进度、结果或当前选择 |
| 理解与决策 | 消除歧义，提供事实、差异、价格、单位或限制 |
| 视觉与表达 | 建立构图、节奏、氛围、品牌记忆、叙事或交互隐喻 |
| 使用保障 | 支持无障碍使用，提供必要的权利、收费与风险信息 |

“填满空间”“增加层次”“显得专业”不能单独成为保留理由。不得为自行加入的元素事后编造品牌目的。

删除试验必须同时看功能与视觉效果：移除后，理解、操作、决策、构图、氛围或辨识度是否受损？确认无损且无独立作用时删除；用途相同且无需独立呈现时合并；有效但非当前所需的信息可以按需显示。无法判断的既有设计默认保留，不因缺少设计文档就认定冗余。

### 设计巧思的辨别

先找页面已有的视觉语言及元素间的关系，再评价单个元素。设计意图可以从整体构图、反复出现的主题、交互反馈和内容关联中观察，不要求每处都有文字说明。审美价值不以新增信息量衡量；一项设计也不必满足所有维度。

| 维度 | 观察什么 |
|---|---|
| 主题关联 | 是否与内容、品牌气质或叙事形成具体关联，例如用电视与频道旋钮表达选片 |
| 构图与节奏 | 是否引导视线、平衡画面、分隔段落或形成有意的疏密变化 |
| 交互映射 | 形式是否帮助理解操作，动作与反馈是否相互对应 |
| 氛围与辨识度 | 是否形成连贯的审美体验或记忆点，移除后是否让页面失去特征 |
| 实际代价 | 是否遮挡内容、争抢主要行动、造成阅读困难或强制等待；用实际页面表现说明 |

有表达价值但干扰任务时，优先减弱强度、降低重复、调整位置或显示时机。例如将开场改为可跳过，保留调台隐喻；降低背景文字对比度，保留构图作用。不能只因非功能性、元素多或形式常见就删除。

对改变页面气质的候选，保留原版，必要时比较保留、减弱与移除的局部效果。单张截图或主观偏好不足以断言设计无效；不把所有审美取舍都交给用户。

## 3. 精简规则

### R01：文案只保留有效信息

删除无用途小字、空泛口号、重复说明和普通访客不需要的制作旁白，例如框架名称、原型制作流程。修订理由放在交付说明中。

- 一个区域通常保留一个主标题，副标题须增加信息。
- 英文眉题、双语、编号和标签须有真实用途，不按禁词机械删除。
- 按钮用具体动作命名，同一动作名称一致；重要后果不能省略。
- 帮助文字回答具体问题并靠近相关对象，保持可读字号与对比度。
- 开发者文档、用户要求的演示标记与必要披露，保留准确说明。

### R02：模块按任务合并

同一内容在多个模块反复展示、同一卖点被换句话复述、展示模块打断主线时，检查是否可以合并或删除。重复也可能承担主题呼应与叙事节奏，先判断它们之间的关系。

保留独有信息、必要对比、用户需要的导航与就地说明。跨页面、独立弹窗、窄屏或长页面末尾的重复可能有用，按实际使用情境判断。不能为了减少模块数，把所有内容塞进一个大区块。

### R03：装饰与容器不过度叠加

检查徽章、背景文字、分割线、边框、阴影、嵌套卡片与展示动效，依据上一节辨别其作用。优先减少已确认干扰任务且缺乏表达价值的叠加，再调整间距、对齐和分组。

删除元素后，处理专用容器、占位高度与异常间距；仍承担布局、点击、状态或无障碍职责的结构要保留。不通过缩小必要文字、降低功能性文字与控件的对比度、裁切内容或隐藏滚动条制造简洁感。装饰性背景可以减弱，但须检查叠加后的可读性。

保留有依据的品牌与叙事表达，不把所有页面统一成相同的极简模板，也不一律禁止图片、渐变、卡片或动效。

### R04：层级围绕核心任务

先明确页面主要服务谁、提供什么、下一步是什么，再调整信息顺序。主要行动应突出，次要行动降低竞争；不机械要求全页只有一个按钮。

关键差异、成本、限制与决策依据应出现在相关行动附近。低频细节可以折叠，但影响选择或操作的事实不能藏起来。删除次要内容后重新检查首屏与整页节奏，不保留无用途的固定空白。

### R05：减少无必要的操作步骤

检查强制开场、仅供展示的绕行、重复选择、入口埋得过深等问题。在授权范围内让用户更直接到达目标，同时保留必要的确认、授权与风险提示。

先核对行为再命名：展示动画不等于播放，本地选择不等于购买。新增入口必须使用已确认的目的地；缺失真实目的地时报告缺口，不虚构播放、支付或开通。

### R06：保护内容、真实性与功能

不得删除用户明确指定的内容、独有事实、核心观点和必要功能。必须保留表单标签、单位、输入限制、错误原因与下一步、必要空状态、可访问名称、有意义的图片说明，以及必要的版权、许可、隐私、收费与风险信息。

不得编造用户数、评分、热门程度、认证、观看记录、更新时间或技术能力。样例与愿景不能包装成已实现的业务结果；真实性不明的原文列为待核实，不用另一项未经证实的说法替换，也不自动往产品页面添加审查小字。

修改代码时检查状态绑定、国际化键、无障碍关系、选择器与测试引用。节点承担的职责未弄清前，不随可见文字一起删除。

### R07：以审美判断校准视觉，优先减弱失衡元素

根据页面已有风格，判断形式与内容是否契合、比例是否协调、视线是否有主次、材质与细节是否连贯。不得仅凭个人偏好认定某种风格高级或低级，也不为“统一”抹平有意的对比与不对称。

视觉对齐同时检查几何关系与风格关系：

| 项目 | 校准依据 |
|---|---|
| 边缘与基线 | 标题、正文、图片、按钮是否沿清楚的网格与基线组织；图标可做光学校正，不强求数学居中 |
| 比例与空间 | 字号、图片尺寸、内边距与模块间距是否形成连贯节奏；关联内容靠近，分组边界清楚 |
| 文字与图形 | 相同职责的标题、按钮与图标保持相近的视觉权重；字重、图标线宽、圆角与描边相互协调 |
| 色彩与材质 | 强调色、饱和度、渐变、阴影与发光是否属于同一套视觉语言，是否过度争抢焦点 |
| 动效 | 幅度、速度、频率与同时运动的元素数量是否符合页面气质，是否打断阅读或操作 |

元素有价值但太突出或花哨时，默认先减弱并检查整体效果：调整相对尺寸或位置、降低装饰色的饱和度或不透明度、收敛阴影和发光、减少效果叠加或动效强度。根据具体失衡选择手段，不机械地全部应用。

主行动、选中状态、错误与重要提示仍须足够清楚。保留有意的视觉焦点和记忆点，不要求每个元素同样醒目。只有减弱后仍有明显干扰，且移除不会损失必要功能或设计表达时，再考虑删除。

## 4. 执行流程

### A. 确定任务和范围

从用户要求、页面与代码判断主要任务及需保留的内容。已有信息足够时直接进行，只有缺失信息会改变取舍时才问。

用户要求按真实落地页处理时，按访客理解和行动评估。已有“概念／作品集”自述不能豁免制作旁白，必要的归属与真实能力边界仍须保留。工作工具、内容阅读、营销与作品展示允许不同的信息密度。

### B. 从整页到局部审查

先识别页面值得保留的视觉主题与巧思，再看内容顺序与核心路径，检查重复模块、装饰、文字、对齐和空间。分类为：保留、改写、合并、视觉校准、减弱、按需显示、删除、待核实。说明失衡发生在哪里、它与哪个元素争抢层级；删除建议还须说明移除损失，不能只写“装饰太多”或“更简洁”。

兼查 CSS 伪元素及 `content`、SVG、滚动和选择后动态更新的内容。截图只能证明可见状态，不能证明业务能力或交互结果。

优先处理对理解和操作影响最大的冗余，不以删除数量或页面长度作为成功指标。

### C. 按授权落实

- **审查请求**：给出可定位的问题、建议动作与理由。
- **精简请求**：落实文案、模块、装饰、层级与相关路径的修改，修正受影响布局。
- **新界面请求**：先确定必要内容与行动，新增元素均通过职责判定。

授权范围外的问题只报告，不顺手重建其他页面。交付说明与审查表不放进产品界面。

### D. 验证结果

检查实际页面和受影响的窄屏布局，确认：

1. 用户更容易看出核心内容与下一步，必要信息仍可获得。
2. 没有空容器、异常大间距、裁切、遮挡或横向溢出。
3. 按钮、选择、切换、表单和相关弹窗仍可用；动态内容不会恢复已删冗余。
4. 键盘操作、可访问名称、必要状态与披露保留。
5. 入口、文案和真实能力一致，待核实项没有被包装成已验证结果。
6. 原有的主题、构图节奏、氛围与交互隐喻仍成立；没有因精简变成缺乏特征的通用模板。
7. 对齐、比例与风格关系协调，主要焦点仍突出；减弱后的装饰没有影响文字、控件和状态的辨认。

只能看截图或源码时说明范围，不宣称已验证交互。发现具体问题后修复相关区域；没有新问题时结束。

## 5. 汇报

简要说明删减或合并了什么、核心内容与功能保留情况、验证结果和未完成项。审查表建议使用“位置｜问题｜处理｜理由”。必要时提供前后对比，不展示所有正常元素或完整内部过程。
